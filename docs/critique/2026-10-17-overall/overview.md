## 2. 使う人が実際にすること（操作と判断）

### X 検索タブ（設定1〜3）
1. 画面上部の「設定1・設定2・設定3」タブ（3 つの保存枠。毎日別々の名前を探す人向け）を選ぶ。初期画面は空（overview.md:12）。
2. 「名前・愛称・ハッシュタグ」欄にチップとして足す（例の文「ぬぬはらさん、#003_FA」、i18n.ts:12）。複数は OR。2 つ以上で「すべてのキーワードを同時に含む投稿だけ（AND検索）」に切り替え可（i18n.ts:47）。
   - 名前を入れると「表記ゆれ候補」（ひらがな・カタカナ・半角カナ・空白なし）が出て、押したものだけ検索に入る（overview.md:6）。敬称の扱いもある（i18n.ts:15）。
3. 必要なら「このアカウントの投稿だけ」（from:）、「絞り込む」（この言葉も含む・画像動画つき・いいね数）、「除外する」（アカウント -from:・キーワード・「ネガティブワード」）、期間（すべて／日付の前後 7日〜3ヶ月／開始日〜終了日）、並び順（最新順・古い順・話題のポスト順）、「前回の検索より後の投稿だけ」を選ぶ（i18n.ts 6-80 行、search-app.tsx）。
4. 「投稿を検索」で X の `x.com/search` が新しいタブで開く。上のボタンが画面外のときは画面下に固定の検索ボタンが出る（overview.md:8、src/components/floating-search.tsx）。
5. 入力は自動でブラウザ（localStorage）に保存。翌日はタブを選んで押すだけ（i18n.ts「設定した内容はブラウザに自動保存されます。」）。
- 判断する所: OR か AND か、引用符で完全一致にするか（「語句を引用符で囲む」i18n.ts:33）、ネガティブワードを使うか、期間の取り方。

## 3. 特徴的な仕組み

- **API を呼ばず URL を作るだけ**: 検索は `x.com/search` と intent URL の組み立てのみ。X の Search API・スクレイピング・ログインは使わない（AGENTS.md「制約」）。そのため X 側の仕様変更（演算子の効き方・文字数上限・ログイン要否）に結果が左右される。
- **文字数の自動調整**: X の検索は約 500 字でエラーになる前提で、上限 500（src/lib/query.ts:56）。ネガティブワードは他の条件を入れた残りに優先順で 490 字まで詰める（query.ts:59, 104）。X で通ると確かめたのは 492 字（overview.md:7）。【持】上限に当たる補助機能は警告を出さず黙って削る（メモリ auto-fit-over-warnings.md）。
- **ネガティブワード辞書**: 手で選んだ日英の悪口語を除外に足す（src/lib/negative-words.ts）。初期はオフ。誤検知ありと画面で断っている（i18n.ts:27）。
- **前回より後だけ**: 前回開いた時刻以降に絞る（src/lib/last-search.ts）。
- **YouTube の無料枠**: `*.list` の 1 ユニット系だけ使い、`search.list`（100 ユニット）は使わない。キーはリファラー制限付きの公開キー（AGENTS.md）。キーの利用制限が実際にかかっているかは【未確認】（NunuDB/ops/egosearch.md:7）。
- **SEO の土台**: 初期 HTML にヘッダー（h1・キャッチコピー・使い方リンク）を出す（Q-053）、WebSite の構造化データ（src/lib/site-metadata.ts:14-25）、ページごとの title・カード（Q-054）。トップの title は「エゴサ支援ツール(ぬ) | X(Twitter)のエゴサ・推しのパブサをまとめて検索」（src/app/layout.tsx:26）。
